## Short post

arcus-provider-runtime v0.9.0 ships today.

→ Web pages are converted as the browser rendered them: content added by JavaScript (and by web components) now reaches the markdown.
→ Articles whose page opens with a short teaser come back whole — one corporate "insights" article went from 363 characters to the full ~2,200 words.
→ Two inputs with the same name (two `paper.pdf`, two videos with one title) each keep their own output instead of overwriting each other.
→ The YouTube NotebookLM fallback works with current `nlm` and fails loudly, with an install hint, when it's missing.

## Pinned-issue

**arcus-provider-runtime v0.9.0 released — rendered pages, whole articles, one output per source**

What you'll notice as a consumer:

1. HTML output changes for pages that build their content in the browser: what you get now matches what the page shows, including code examples and other content kept inside web components. Pages are no longer downloaded a second time.
2. Pages whose first `<article>` is a hero/teaser (component-CMS "insights" pages, blog index pages) return the whole page instead of the teaser. Navigation boxes, breadcrumbs, cookie and "you're leaving" dialogs are dropped, even when nested.
3. Two sources that map to one name each get their own files: the first keeps `<slug>.md`, later ones get `<slug>--<hash>.md`. Read the final name from the run's `success` / `cache_hit` event. Run one extraction at a time per output directory.
4. Custom providers should name their output from `ExtractionContext.slug`; the writers now refuse to replace another source's files (`SlugTakenError`, exit 10) instead of overwriting them.
5. The YouTube NotebookLM fallback needs `notebooklm-mcp-cli>=0.9.4,<1`; `arcus --check` shows the installed version and whether you're logged in.

Full changelog: https://github.com/polleoai/arcus/blob/main/CHANGELOG.md#090--2026-11-24

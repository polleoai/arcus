## Pinned-issue

**arcus-provider-runtime v0.7.0 released — reveal.js slide-deck extraction**

What you'll notice as a consumer:

1. Fetching a reveal.js deck URL through the `html` provider now returns
   clean, ordered per-slide markdown instead of an empty body or text still
   carrying raw HTML entities.
2. Each slide is a discrete segment with a slide-number locator
   (`{"segment": i, "slide": i+1}`), mirroring the `docs` provider's
   per-sheet/per-slide segments — so downstream consumers get structured
   slides, not a blob.

Full changelog: https://github.com/jivebug/arcus/blob/main/CHANGELOG.md#070--2026-07-01

## Substack / newsletter

Talk decks aren't articles, and the generic HTML-to-markdown path treated them
like one — returning an empty body or a wall of text still leaking
`&middot;` / `&amp;` entities. v0.7.0 adds a depth-aware reveal.js extractor to
the `html` provider: it walks leaf `<section>` elements (preserving nested
vertical slides a flat regex would merge or drop) and emits one clean segment
per slide. This closes out a stopgap Athena carried on its own side since
1.6.1 — once Athena adopts this release, it retires that fallback entirely.

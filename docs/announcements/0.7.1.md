## Short post

arcus-provider-runtime v0.7.1 ships today.

→ New opt-in URL guard: give arcus a policy function and it checks every URL it fetches — redirects, browser sub-requests, yt-dlp requests.
→ Refusals are reported (new exit code 12, `UrlRefusedError`), never silently empty.
→ No guard set = no behavior change.

## Pinned-issue

**arcus-provider-runtime v0.7.1 released — validate redirects and sub-requests against a caller policy**

What you'll notice as a consumer:

1. `set_url_guard(policy)` (or the `using_url_guard(policy)` context manager) applies your URL policy to every fetch arcus makes, including redirect hops and headless-browser sub-requests.
2. A refused page returns exit code `URL_REFUSED` (12) from `factory.run`, or raises `UrlRefusedError` from a provider; refused sub-resources are blocked while the page still extracts.
3. If you pass arcus URLs you don't control, upgrade and install a guard. If you don't set one, nothing changes.

Full changelog: https://github.com/polleoai/arcus/blob/main/CHANGELOG.md#071--2026-11-22
